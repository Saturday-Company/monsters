# Languages of the app (D-153)

Monsters is English first, with Italian as a choice. This page is the guide for whoever writes or moves
visible text.

## Two languages, two settings

- **The app's language** (`en` or `it`): the UI, the core's messages (errors, notices, receipts, "To
  review"), Telegram, the desktop app's menus and pages. It lives in `settings.json` (`language`), is
  written at the first start (an install that already had an account stays Italian, a new one takes the
  system's language) and changes from Settings → General or from the first screen. The core exposes it in
  `GET /api/setup-status` (public) and `GET /api/settings`, and changes it with `PUT /api/settings/language`.
- **The monsters' language**: the `lingua` answer of the onboarding (`it`, `en`, `es`, `fr`, `de`), the
  language they write notes and replies in. It is not the app's language.

## Where texts live

Every visible text lives in a dictionary next to the code that shows it, in a file named `*.strings.ts`:

```ts
import { defineStrings } from '../../lib/i18n.ts'; // web; the core and the desktop use `pick` from @monsters/shared

const en = {
  title: 'Settings',
  notes: (n: number) => (n === 1 ? '1 note' : `${n} notes`),
};
const it: typeof en = {
  title: 'Impostazioni',
  notes: (n) => (n === 1 ? '1 nota' : `${n} note`),
};

export const settingsStrings = defineStrings({ en, it });
```

- The Italian dictionary has the English one's type: a missing key or a parameter of the wrong type fails
  the typecheck.
- An entry is a string or a function with typed parameters. Use a function for every plural, every
  sentence with a value in it and every agreement (Italian genders and articles): whole sentences, never
  pieces glued together in the code.
- Call the dictionary where the text is needed (`settingsStrings().title`), not at module load: the
  language can change while the app runs. In the web UI a change of language remounts the whole tree; a
  text kept outside React (a store, a cache) must be picked again when it is shown.
- Dates, numbers, money and lists go through the formatters of `@monsters/shared` (`formatDate`,
  `formatNumber`, `formatList`, `compareText`), never with a hardcoded `'it-IT'`.
- Identifiers stay as they are, whatever language they are in: routes (`#/impostazioni`), onboarding answer
  ids, settings keys, event types. They are not copy.
- The core picks its texts when it writes them: events already in the log stay in the language they were
  written in.

## Texts the models read

Prompts, AGENTS.md templates, system reminders, tool descriptions and the results a tool sends back to the
model live in `*.prompts.ts` files next to the code, in two *families* (wave 3 of D-153):

- The family is the app's language when the text is produced (`appLang()`, or `pick({ en, it })` at the
  moment of use). The Italian family is the one the evals measured: it never changes by a character (a new
  rule makes a new version). The English one is a faithful translation: same structure, rules, examples,
  emphasis and placeholders, so a model behaves the same.
- The monsters' writing language is not the family: an English prompt says "Always in Italian". Name it with
  `writingLanguageName(word, lang)` from `@monsters/shared`; readers accept the word of either family.
- Files on disk (AGENTS.md, `profilo.md`, MEMORY.md) keep the family they were written in. Code that reads or
  rewrites them reads both families (`agents/instructions.ts`, `team/team-manager.ts`); changing the app's
  language rewrites none of them.
- A marker a prompt asks the model to write and the code then looks for has a word per family
  (`agents/markers.prompts.ts`), and the reader accepts both. Word lists that read what models and users
  write (negations, verbs, stopwords…) cover English and Italian, marked `// i18n-ignore`.
- UI labels quoted in a prompt come from the dictionaries, never retyped.
- Tests run in English; a test of the Italian family calls `inLang('it')` (`packages/core/test/prompt-lang.ts`)
  and starts its core in `langHome('it')`: its Italian assertions are the proof that the Italian did not move.

## The guard

`node scripts/check-i18n.ts` (part of `pnpm lint`) fails on text written by hand in the product's sources:
text between JSX tags, visible attributes (`aria-label`, `title`, `placeholder`, `label`…) set to a string,
and any other string that reads as Italian. `*.strings.ts`, `*.prompts.ts`, files under `i18n/`, the tests and the web UI's
mock are not checked. A line that is data, not copy (the words of a regex, an id), is marked with a
`// i18n-ignore` comment on it or on the line before.

While the texts move into the dictionaries, `scripts/check-i18n.baseline.json` lists how many findings each
file still has: a file may not get more. After moving texts, run `node scripts/check-i18n.ts --update`.

## Writing the English

Plain, short, friendly, second person, like the Italian. Product English, not a literal translation: say
what a native speaker would say in the same place. Sentence case for titles and buttons. Typographic
apostrophe `’` as in the Italian copy. The monsters speak in the first person ("I couldn’t…").

Small rules that came out of the first review of the English UI:

- US spelling ("defenses", "recognize", "organized").
- Clock times come from `timeOptions()` (`@monsters/shared`): "4:00 PM" in English, "16:00" in Italian. Never
  write `hour: '2-digit'` by hand.
- Quotes belong to the dictionary: “…” in English, «…» in Italian. Never type them in a component.
- A sentence with a count agrees with it ("is sent" / "are sent"): the entry takes the number.
- Say "message Titan", not "write to Titan"; a monster is "it" in system sentences ("message it from its chat").
- The Italian dictionaries never call a function that depends on the app's language (`toNameIt`, not `toName`):
  an Italian sentence must read the same whatever language is on.
- Labels that must fit a narrow bar (the phone tabs, the god's line, the search field) are short on purpose:
  check them at 390 px.
